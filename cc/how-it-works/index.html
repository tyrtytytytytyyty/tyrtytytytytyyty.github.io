03 · How it works

One text, followed all the way down.

A customer sends "is HV-4471 still today?" This is everything that happens before they get an answer, from the network to the switches inside the box.

Scroll ↓

The trace

Eleven steps. Two of them leave the box.

  1. The message arrives Network

    The text goes from the customer's phone to a cell tower, through their carrier, to the business's rented text number. The number's provider turns it into a web request and sends it over HTTPS to my box. Email, website chat and Messenger arrive the same way, as a web request.

    HTTPS means the trip from the provider to my box is encrypted with TLS. Anyone in the middle sees scrambled bytes.

  2. Who is this? My box

    The sender's number is cut down to its last 10 digits and compared against the business's own records: the owner, the crew from their job applications, the customers from their bookings. Whatever it matches decides the role. If nothing matches, they're a stranger.

    # (706) 555-0142, 7065550142 and +1 706.555.0142 all become the same thing
def resolve_role(biz, phone):
    p = digits(phone)
    if p == digits(biz.owner.phone):        return "owner"
    if p in {digits(s.phone) for s in biz.staff}:     return "staff"
    if p in {digits(c.phone) for c in biz.customers}: return "customer"
    return "prospect"

  3. What are they allowed to see? My box

    Code picks the records, not the AI. A customer gets only the tickets tied to their number. A crew member gets only the jobs assigned to them, with no prices. The owner gets everything. A stranger gets only what's public.

    If someone types a ticket number that isn't theirs, it's handled exactly like a ticket that doesn't exist, so typing ticket numbers at random tells you nothing.

    if role == "customer": visible = [j for j in jobs if j.customer == sender]
if role == "staff":    visible = [j for j in jobs if j.assigned_to == sender]
if role == "prospect": visible = []          # public info only
# everything not in `visible` is never loaded into the conversation at all

  4. The math happens here, not in the AI My box

    "What's today's profit?" is added up by code from the actual numbers before the AI is involved. AI models are good at writing sentences and bad at arithmetic, so the system never asks it to do math. It only gets the finished number to phrase.

  5. Names and numbers are swapped out My box

    Every name, phone number, address, gate code and ticket number is replaced with a placeholder like [CUST_NAME_1]. There are two layers:

    Records: the system knows exactly which fields are private, so it swaps those exactly. The message itself: what the person typed goes through the privacy filter tested on 11,000 messages. It uses pattern rules for numbers, cards and emails, a language model that spots names, a known-sender check, and a word-frequency filter that tells "Hope" the name from "I hope".

    what the customer typed:  hey its Dana, is HV-4471 still today? what time
what the AI receives:     hey its [SENDER_FIRST_1], is [TICKET_1] still today? what time

    The list of which placeholder means what lives only in the box's memory, for that one conversation.

  6. The question goes to a rented AI model Leaves the box

    The blanked message and the blanked records go over HTTPS to a rented model through OpenRouter. The request is only allowed to go to endpoints that don't store data (zero data retention, data collection denied). If no such endpoint is available, the request fails instead of falling back to one that keeps data.

    It costs about a hundredth of a cent per reply.

  7. The AI answers with placeholders Rented model

    It writes something like "Yes, [TICKET_1] is today at 2:15 and [STAFF_FIRST_1] is your tech." It never learns who Dana is, who the tech is, or where anyone lives. It also has rules: answer only from what it was given, never invent a ticket or a time, and nobody gets more access by claiming to be the owner or telling it to ignore its rules.

  8. Real details go back in My box

    Back on the box, every placeholder is swapped back for the real value: "Yes, HV-4471 is today at 2:15 and Dre is your tech."

  9. The guard checks the reply My box

    Last check before it sends: the reply is compared against every private value this person is not allowed to see, including other customers' names, numbers, addresses, gate codes, prices and the day's revenue. If even one shows up, the reply is blocked and handed to the owner instead.

    It shouldn't ever fire, because the AI was never given those values. It runs on every message anyway, to prove it.

  10. Booking and hand-offs My box

    If someone wants to book, the AI adds a line like BOOK: tune-up | Thursday 3pm. Code strips it out and puts it in front of the owner to confirm. Refunds, complaints and anything it can't answer get a HANDOFF line and go to a human.

  11. The reply goes out Network

    It goes back the way it came: over HTTPS to the text provider, through the carrier, to the customer's phone. A few seconds end to end.

All the way down

What "on my box" physically means.

Step 2, "is this the owner's number?", is one comparison. Here's what that comparison actually is.

  1. Text becomes numbers

    "7065550142" is stored as ten bytes. Each character is a number: "7" is 55, "0" is 48. Each byte is 8 bits, 1s and 0s.

  2. Bits are charges

    While the program runs, those bits sit in the box's memory (DRAM) as tiny stored charges. Charged is a 1, empty is a 0. That's also where the placeholder list lives, and why it disappears when the conversation ends or the power goes off. It's never written to disk.

  3. Comparing is gates

    The processor checks the two numbers byte by byte. Inside, the comparison is built from logic gates: an XOR gate outputs 1 when two bits differ, and if every XOR comes out 0, the numbers match. Each gate is a handful of transistors, microscopic switches that turn on or off when a voltage hits them.

  4. Billions of switches, one decision

    Billions of those switches flipping is what "the system knows it's the owner" physically is. Every access decision on this page comes down to that: a comparison made by code on hardware I control, never a guess by an AI.

Honest limits

What it doesn't do, said plainly.

Text messages aren't end-to-end encrypted. Carriers can see SMS. The privacy guarantee here is about the AI company, which never sees who anyone is. It isn't about the phone network.

A phone number is strong proof, but not perfect. Numbers can be spoofed or a phone can be stolen. For the owner's money questions, a PIN on top of the number is the next thing on the build list.

Freely typed names are the hardest part. Names already on file are swapped exactly. A name someone types that the business has never seen is caught by the filter about 88% of the time in testing. Numbers, phones and cards score higher. The proof page has every number.

Where it runs today: the system and tests run on my MacBook. Production moves to a dedicated Mac mini with battery backup when the first install goes live. Text-number service (a rented number per business) gets set up per client.
